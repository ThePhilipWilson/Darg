# Workbench

Philip's one app for everything: per-project boards, notes, docs, code, agents, consoles and tools. Native Avalonia (C#, .NET 10), one codebase for Windows, Mac and mobile. The plan and decisions live in Philip's Obsidian vault under `Code/Workbench/` (PLAN.md, the mockup, MORNING.md, PHONE-PLAN.md); the folder on this machine is in `CLAUDE.local.md` (not committed).

## Layout

- `src/Workbench.Core`: no UI. `InstanceConfig` (an instance's projects, in `%APPDATA%/Workbench/<instance>/instance.json`; `WORKBENCH_INSTANCE`, `WORKBENCH_HOME`), `BoardStore` (boards in Tatty's markdown format, so Tatty and Obsidian see the same files), `AgentSession` (a real Claude Code session run headless over stream-json), `ChildProcesses` (everything Workbench starts dies with it).
- Artifacts (`Artifacts.cs`): HTML pages agents make, kept in `<instance>/projects/<project>/artifacts/<agent id>/`, never Claude's cloud. Each project agent gets that folder (`--add-dir`) and `ArtifactStore.Briefing` (`--append-system-prompt`; no `<>"&|` in it, it goes on a command line). `ArtifactServer` serves them on `http://localhost:47817/` (any free port if taken) with a `workbench.send()` bridge put into each page; a send POSTs to a URL carrying the instance's token (`artifact-token`) and arrives at the agent that made the page as a message starting "From artifact". `/file/<absolute path>` serves images only. An image review is a `*.review.json` (title, note, folder, rows of id / original / candidates) that Workbench shows through its own picker (`Review.html`, embedded in Core) rather than a page the agent writes; Send replies `id: file | note` per row (`original`, or `NEEDS PASS` for no pick), so a script can take it as it comes. The Artifacts section shows them in a `NativeWebView`. WebView2 doesn't show up in `tools/shot.ps1` captures (PrintWindow); check a page through UI Automation (Chrome elements, Invoke pattern) or a screen copy.
- Also in Core: `NoteStore` (the notes wall: one .md per note with Obsidian properties; `MakeTicket` uses `BoardStore.Create`, which names files as Tatty does; a note with a ticket shows in a Ticketed column whatever its `column:` says, and `SyncArchive`, run on every wall reload, which a board file changing also triggers, moves it to `notes/archive/` once its card is Completed and back if the card reopens), `ClaudeDraw` (the claude-draw daemon on 7331, shared by every Claude Code session: Workbench only reads its `/state`, opens the canvas and starts a blank one; agents ask and collect through their own plugin tools, so ✎ Draw sends the agent a message rather than calling the daemon). `Preview` / `DevServer` (the Site section: a project's `preview` in instance.json, else the first repo whose package.json has a `dev` script; the server runs in its own job via `ChildProcesses.Group`, because a tree kill left npm's node running).
- The Site section's browser is `NativeWebView` (Avalonia.Controls.WebView, WebView2 on Windows). It is a native window, so nothing Avalonia draws (Fettle, popups) shows over it.
- Desktop extras: `Notifier` (Windows toasts carrying project and agent ids; clicking opens that agent; the Desktop project targets `net10.0-windows10.0.19041.0` when built on Windows, plain `net10.0` elsewhere, and code for toasts sits under `#if WINDOWS`), `MascotViewModel` (Fettle, the corner mascot, once called Bench: one session for the instance with `--add-dir` for every project's boards, notes and repos, and a briefing on the file formats via `--append-system-prompt`). Transcript templates live in `App.axaml`'s `Application.DataTemplates`, shared by the agents view and Fettle.
- Flows (multi-agent, e.g. designer → engineer → QA): `FlowStore` in Core reads them from the instance's `flows/` folder, one markdown file each (`# Name`, `Max rounds: n`, a `## Role` section per stage; a stage whose brief starts `Sends back to: Role` is a checker that ends with `VERDICT: PASS|FAIL`; any stage can end with `FLOW: STOP`). The starter `designer-engineer-qa.md` is written the first time. `FlowRun` (Desktop) runs one: an agent per stage, each handed the last reply of the ones before, fully automatic. Started from a card (context menu, card panel) or the Agents view's flow picker; `WORKBENCH_FLOW=<name>` with `WORKBENCH_AGENT` runs one without clicking. A run lasts only while the app does.
- `src/Workbench.Desktop`: the Avalonia app. MVVM with CommunityToolkit.Mvvm; views in `Views/`, view models in `ViewModels/`. Every project's view stays alive across tab switches, so agents and terminals keep running.
- `tests/Workbench.Core.Tests`: xunit. `WORKBENCH_LIVE=1` also runs the live agent test (a Haiku turn through the real CLI).

## Agents: the protocol

`claude -p --input-format stream-json --output-format stream-json --verbose --permission-prompt-tool stdio`. The `--permission-prompt-tool stdio` flag is what routes permission prompts to the host as `control_request` / `can_use_tool` **and** what makes `AskUserQuestion` available at all (without it the tool is missing from print mode). A question is answered by allowing it with `answers` (question text to label) added to its input. Permissions otherwise follow the person's own Claude settings: an edit their settings allow runs without a prompt, as in the terminal. Verified on Claude Code 2.1.325, 2026-11-16.

## UI rules learned from Philip's use

- **A list must read as a list of things, not of times or cut-off text.** Chats and agents went out named "Bench · 11:00" and the first 40 characters of a prompt; it annoyed him on sight (2026-11-17). When a screenshot shows a list, check that a stranger could tell its rows apart and say what each is; generated items get a real title (`ChatTitle`).
- **Structure on disk shows as structure on screen.** A folder of docs or files is a tree that expands, not a flat list of every file (2026-11-17).
- **Drag and drop shows the thing moving** (`DragLift`), never the OS drag with nothing under the pointer.

## Building and checking

- `NUGET_PACKAGES=D:/nuget/packages` (C: is small). `dotnet build`, `dotnet test`. `dotnet test` rebuilds only Core and the tests, not the app: run `dotnet build` before launching the exe to check a change, or you're looking at the old build.
- GitHub calls go through `gh` with the project's account's token (`gh auth token --user <account>`) in `GH_TOKEN` for that call only; the active gh account is never switched. A private repo seen with the wrong account answers 404.
- See it without clicking: `WORKBENCH_SECTION=Board|Agents|Preview|Terminal` opens that section of the first project; `WORKBENCH_AGENT="prompt"` starts an agent there (in `WORKBENCH_AGENT_CWD` if set). `tools/shot.ps1 -ProcessId <pid> -Out x.png` captures only the app's window (PrintWindow, works when covered). UI Automation can press its buttons (Avalonia exposes them by name; find them among the window's Button descendants, as a `NameProperty` condition on the whole tree can miss), and `AutomationElement.FocusedElement` says what has focus. Launch it with `Start-Process -WindowStyle Normal`: from Claude's shell without it the process runs with no window at all.
- **The copy Philip uses** is published: `pwsh -File tools/publish.ps1` builds Release into `D:\Apps\Workbench` (closing a copy running from there first; agents are saved after every turn) and makes Start menu and desktop shortcuts. Debug builds in `bin/` are for checking. **An agent running inside Workbench can't publish:** closing the installed copy kills the agent's own host (it did, twice, 2026-11-16), so the script refuses; ask Philip to run it from a terminal, or to use the header's ⟳ menu. publish.ps1 writes `source.txt` (the repo) into the install folder; ⟳ Update builds that repo into `<install>.next` while the app runs, then a helper (`Updater`, started outside the app's job with `ChildProcesses.StartOutsideJob`) waits for the app to close, copies the build in and starts it again. A copy without `source.txt` (a debug build) can only restart.
- A crash in a view goes to `crash.log` in the instance folder instead of closing the app; read it after anything odd.
- Scratch output goes in `.shots/` (ignored). For anything that writes cards or notes, point the app at a throwaway instance (`WORKBENCH_HOME=.shots/home`, with its own `instance.json` and board), never at the real vault boards.
- The exe is `src/Workbench.Desktop/bin/Debug/net10.0-windows10.0.19041.0/Workbench.Desktop.exe` on Windows.
